# Our current platform versus the investigated systems

Date: 2 November 2026. Findings refer to the individual reports; comparative statements are capability/mechanism assessments, not measured accuracy or speed rankings.

## Existing implementation baseline

Inspected foundation: `backend/app/analysis/pipeline.py:analyze`; `backend/workers/typescript/index.cjs`; `adapters/{next,express,wrangler}.cjs`; `analysis/configuration.py:augment`; `evidence/validation.py:validate`; `contracts.py`; `persistence/store.py`; `graph/{projections,exploration}.py`; and React Flow/ELK components.

Our strengths are controlled public GitHub/ZIP intake, a restricted compiler host, no target install/build/execution, implementation-body-based local calls, source hashes/ranges, explicit unknowns, one saved graph and bounded views. Our file groups and role labels remain basic. No OS-enforced containment, broad labelled accuracy corpus or enterprise-scale benchmark is established. Prior recorded 61-test results are functional/regression evidence and were not rerun for this research.

## Per-project comparison

| Reference | What overlaps | More developed/documented area | Missing in our product | Realistic lesson | Substantial effort / avoid |
|---|---|---|---|---|---|
| RepoDNA | Intake, artifacts, routes, static graphs, evidence and exploration | Multi-path browser/Python analysis, inventory diagnostics and route-oriented navigation | Python syntax support, broad export and some mount patterns | Adopt coverage categories, route-handler fixtures and source-linked exploration | Porting its whole app would discard compiler binding; avoid global name matches as facts and fixed confidence percentages |

| Joern | Typed graph/evidence and static source | CFG/data dependence and extensible semantic passes | Program-point values and explicit enrichment layers | Add narrow bounded flow facts, rule versions and limitations | Full CPG/runtime integration substantial; defer unless it closes a measured gap |
| CodeSee | Interactive maps and source/detail exploration | Documented collapsed/focused maps, tours and PR context | User-guided views/change review | Separate canonical findings from saved view state | Extraction internals unknown; do not infer correctness from editable maps |
| GitDiagram | Repository intake, saved diagram and structured validation | Answer-first semantic presentation and graph compiler | Equivalent clarity/default story | Dedicated semantic view contract and safe export later | AI generation violates core requirement; path validation does not verify relationships |

## The six foundation problems revisited

| Our issue | What this research changes | Next concrete action |
|---|---|---|
| Variable misunderstanding | Joern confirms the value of explicit bounded reaching-definition stages; RepoDNA heuristics are not a stronger substitute | Correct stale initializer handling, then supported program-point value domain |
| Missing source | Inventory/parse/outcome separation is a practical precedent | Include production candidates deliberately; report exclusion reasons and scope |
| Missing routes | Dedicated syntax/framework adapters and mount reconciliation are workable | Root/nested Next tests and supported Express handler/mount identity |
| Frontend/backend mapping | None of the reviewed UI features proves a generic solution | Destination/context/configuration-aware linker with supported method/path matching |
| Folder responsibilities | Understand grouping overlays and StructSAR evaluations separate grouping from raw files | Evidence-based roles, mixed/shared ownership, no directory→service promotion |
| Architectural correctness unmeasured | Partition metrics complement, but cannot replace, typed-edge truth | Positive/negative fixtures and held-out labelled repositories |

Cross-file/project resolution and configuration-to-resource identity are dependencies of several rows. The most consequential gap is not missing a graph database; it is the lack of sufficient semantics to establish cross-source relationships.

## Integration constraints

Keep FastAPI/Python, compiler worker, SQLite, canonical evidence and React Flow/ELK. Contract enrichment should be versioned rather than inserted as arbitrary unvalidated fields. Providers may contribute facts but cannot publish separate authoritative application graphs. No dependency addition follows merely from appearing in a reference stack.

The immediate target remains a complete source-to-resource chain. The research gives better design patterns and test expectations; it does not justify switching priorities to containers, search infrastructure or UI feature accumulation.
